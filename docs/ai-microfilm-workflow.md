# AI 微电影工作流

## 从意图到整片

单片默认使用一个 EP001 容器。先明确主角现在想做什么、为什么不能轻易实现、最后作出什么选择，以及观众离场时理解发生了什么变化。全片结构写入创作简报，导演阐述可选；短片无需编造下一集压力。
剧本给出可见行为、对白与声音；分镜决定观众看哪里、何时知道什么。视频提示词执行分镜，不能重新编剧情。剪辑依据已有素材作取舍；缺失关键行动就回到分镜补拍，不用旁白掩盖。

## AI 制作边界

参考图分为资产提示词 IMG、待挂图计划 PLAN 和已查看的真实图 REF。角色参考解决身份，场景参考解决空间，起始帧解决本镜状态。每个镜头列明各图的用途，不能混用。
复杂手部接触可拆为动作发起、物件特写、接收者反应；多角色同框可由空间建立镜和单人覆盖保持关系。是否采用取决于故事，不能为了省生成成本删掉关键选择。
时长分清全片目标、分镜声明、生成片段与剪辑可用区间。供应商限制必须来自所选模型档案，不按猜测填入。生成与分镜时长保持一致，剪辑在真实素材范围内选取入出点。
环境声可以连接镜头，音乐不能替人物制造不存在的情绪变化。内置渲染不支持的复杂转场、J/L cut 或混音交给实际外部后期，交付前验证结果。

## 升级与兼容

新建项目默认 16:9、一部；目标秒数未知时保持 null。旧配置不改写；旧短剧 rhythm_profile 若已接受仍有效，转为微电影前须明确哪些约束被创作者撤销，不能静默忽略。
技能名、JSON 字段、中文文件名、EP/SHOT/MOTION ID 和 Dashboard 路由保留。界面的“集”是兼容容器名称；无需重命名目录即可创作整片。
不要把已有连续剧的多个 EP 直接合并覆盖到 EP001。先保存原项目，再在新项目选择改编范围，逐一重建来源和引用。

## 完成标准

文本交付：承诺的范围完整，剧本到镜头和提示词的引用可追溯；不声称媒体已经完成。
成片交付：真实素材可读、关键剧情和结尾完整、画幅与时长可核对、字幕对白和尾音可用，缺口如实列出。独立审查与作者自检必须区分。
