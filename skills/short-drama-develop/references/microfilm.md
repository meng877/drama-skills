# 微电影故事开发

**craft_default · FILM-03**：单篇进入本分支后完成以下步骤，替代主流程中系列引擎、分集地图和节奏档案步骤。

1. 在 `项目开发/creative-brief.md` 写清主题疑问、观众体验、主人公欲望、阻力、关键选择、代价、结尾变化，以及画幅、目标总时长与可用制作资源。未知不编造。
2. 在同一简报写“全片结构”：起始状态 → 引发行动 → 行动与后果 → 决定性选择 → 结果与余韵。结构可以非线性，不强制三幕比例或反转数量。每段交代情绪变化及可见/可听的表达方向，不代写场景对白。
3. 明确结束的是哪条人物行动或关系线，哪些信息有意留白。开放结尾也要完成本片承诺，不靠下一集回答本片主要问题。
4. 改编长材料时选择能独立成立的一条人物线或事件，保留来源与改动依据；不要把整本小说压成梗概串讲。adaptation-map 仍按原协议记录。
5. 以角色造型、地点、群演、手部互动、复杂运动、口型和声音列出制作负担及替代实现。建议不能偷偷改变已定情节。
6. 需要导演阐述时使用原 director-brief 交接；不要求 story-engine、series-arc 或 episode-map，也不要求生成 rhythm_profile。

**reviewed_invariant · FILM-04**：交接核对因果、人物选择与结尾承诺，给具体依据；“没有爆点”不是缺陷。
**taste_option**：沉默、观察性场景、慢节奏和开放结尾均可成立。强情节与快剪同样可选，不把微电影等同于慢片。
